# Registration window precedence and public stepper coherence

- Investigated the Sillico live registration blocker on `/sillico/events/divini-sapori/register` and confirmed the public flow was still applying the organizer fallback rule `maxAdvanceDays = 1` even though the event dates already had explicit sales windows opened from today.
- Corrected booking-window precedence in `lib/passreserve-booking-window.js` so explicit event-level or occurrence-level sales-window opening/closing times override organizer fallback booking rules instead of being combined with them.
- Added focused regression coverage in `test/passreserve-booking-window.test.js` for explicit sales-window precedence on both opening and closing constraints while preserving organizer fallback behavior when no explicit event/date window exists.
- Hardened the public registration wizard in `app/[slug]/events/[eventSlug]/register/registration-flow-experience.js` so it auto-selects the first actually bookable date, clamps the active step to the highest valid state, disables inaccessible step buttons, and keeps `Continue` / step navigation coherent when no valid date or incomplete attendee state exists.
- Clarified organizer admin copy in Settings, Events, and Schedule so organizers understand that explicit event/date sales windows override organizer fallback booking rules, which should reduce the chance of future configuration confusion like the Sillico case.
- Verification completed with `npm run test -- test/passreserve-booking-window.test.js test/passreserve-registrations.test.js`, `npx eslint lib/passreserve-booking-window.js app/[slug]/events/[eventSlug]/register/registration-flow-experience.js app/[slug]/admin/settings/page.js app/[slug]/admin/events/page.js app/[slug]/admin/schedule-page-content.js test/passreserve-booking-window.test.js`, and `npm run build`.
